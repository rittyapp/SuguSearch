# ローカル Wi‑Fi / LAN で Everything に接続するときの注意

すぐサーチ は **Everything の HTTP サーバー** に問い合わせて検索します。  
同じ社内・自宅の **ローカル Wi‑Fi（または有線 LAN）** で、別 PC から使うときの注意を **サーバー側（Everything を動かす PC）** と **クライアント側（すぐサーチ を使う PC）** の両方に分けて書きます。

画面操作の基本は [usage.md](usage.md)、アプリの準備は [../README.MD](../README.MD)。

---

## 全体のイメージ

```
[クライアント PC]  --Wi‑Fi/LAN-->  [サーバー PC]
 すぐサーチ 検索                  Everything（HTTP :8888 など）
 結果の「開く」「コピー」          インデックス（ローカル／NAS）
```

- **検索の問い合わせ** … クライアント → サーバーの HTTP（例: `http://192.168.1.10:8888/`）
- **ファイルを開く・実体コピー** … クライアントが **自分から見えるパス** に届く必要がある（HTTP とは別）

「接続テストは成功するのに、ダブルクリックで開かない」は、だいたい後者の問題です。

---

## 前提チェック（両方）

| 確認 | 内容 |
|------|------|
| 同じネットワーク | 同じ社内／自宅 Wi‑Fi（または有線）。**ゲスト Wi‑Fi・AP 分離**だと PC 同士が話せないことが多い |
| インターネット不要 | 外のネットは不要。ルーター内の通信だけでよい |
| ポート番号を揃える | サーバーで開いたポート（よくあるのは `8888`）を、クライアントの接続設定でも同じにする |
| セキュリティ | 社内 LAN でも、可能なら Everything 側で **ユーザー名／パスワード** を付ける |

---

## サーバー側（Everything を動かす PC）

ここが「検索エンジン本体」です。止まっていると、どのクライアントからも使えません。

### 1. Everything の HTTP サーバーを有効にする

1. Everything を起動する（常駐推奨。スリープすると応答しなくなる）
2. **ツール → オプション → HTTP サーバー**
3. HTTP サーバーを **有効** にする
4. **ポート**（例: `8888`）を控える
5. 可能なら **ユーザー名／パスワード** を設定する（LAN 公開時は特に推奨）
6. 「ローカルホストのみ」「localhost のみ許可」のような制限がある版では、**他 PC から使える設定**にする

サーバー自身のブラウザで次が開けば、まず HTTP 自体は生きています。

```text
http://127.0.0.1:8888/
```

サーバー PC での確認・ファイアウォール許可は、同じフォルダの **ツール1本**で行います（次節）。

### 2. この PC の LAN IP を知る

クライアントが打ち込むのは `127.0.0.1` ではなく、**このサーバー PC の Wi‑Fi/LAN の IPv4** です。

例:

- `192.168.1.10`
- `192.168.0.25`

調べ方の例:

- コマンドプロンプトで `ipconfig` → 「ワイヤレス LAN」または「イーサネット」の **IPv4 アドレス**
- すぐサーチ を **このサーバー PC 上**で開き、接続設定の **「自身に接続」**（自分の IP を入れてテスト）

DHCP のままだと、再接続のたびに IP が変わることがあります。  
長く使うなら、ルーターで **DHCP 予約（固定割り当て）** するか、変わったらクライアント側のホストを直してください。

### 3. サーバー PC 用ツール（診断 + ファイアウォール）

他 PC から繋がらないときは、まず **Everything がある PC** で次を1回実行します。

| ファイル | 誰が使う | 用途 |
|----------|----------|------|
| [everything-http-tool.bat](everything-http-tool.bat) | **サーバー PC** | 診断（ID/パス）＋ファイアウォール許可 |
| [everything-http-remote-check.bat](everything-http-remote-check.bat) | **他 PC（クライアント）** | そのサーバーへ届くか疎通チェック |
| [everything-http-tool.ps1](everything-http-tool.ps1) | （共通本体） | 上の bat から呼ばれる |

#### サーバー PC でやること

1. 動いている Everything・`Everything.ini` から **HTTP の ID/パスワード・ポート**を読む  
2. 待ち受け／疎通を確認する  
3. ファイアウォールで TCP **8888** を Private 受信許可する（UAC で「はい」）

ログ（隣に1つ・上書き）:

```text
everything-http-tool-011012.log
```

Everything を動かしている **同じ Windows ユーザー**で実行してください。  
（パスワードは ini が平文のためログにも出ます。）

#### 他 PC から「届くか」だけ見る

サーバーにログインせず、クライアント PC で `everything-http-remote-check.bat` を実行し、サーバー IP・（必要なら）ユーザー／パスワードを入れます。

- 分かること: ping/TCP、HTTP 401/200、**この PC からの接続可否（日本語）**
- 分からないこと: 相手の `Everything.ini`・プロセス一覧（リモート侵入が必要なため）

ログ例:

```text
everything-http-remote-011012.log
```

引数でも可: `everything-http-remote-check.bat 192.168.1.10 8888 ユーザー名 パスワード`

ポートが `8888` 以外のとき（サーバー側ツール）:

```text
everything-http-tool.bat 9999
```

手動でファイアウォールだけ入れる場合（管理者 PowerShell）:

```powershell
New-NetFirewallRule -DisplayName "Everything HTTP 8888" -Direction Inbound -Protocol TCP -LocalPort 8888 -Action Allow -Profile Private
```

### 4. インデックスの「パスの見え方」を決める

Everything が返すのは **サーバー PC から見たパス** です。

| インデックスの内容 | クライアントでの開きやすさ |
|--------------------|----------------------------|
| NAS の UNC（`\\サーバー\共有\...`） | 同じ共有に届くなら **開きやすい** |
| サーバーの `C:\` `D:\` などローカルだけ | クライアントにはそのドライブが無いので **開く・実体コピーは失敗しやすい** |
| サーバーだけが持っているマップドライブ `S:\` | クライアントの `S:\` と中身が違う／無いことがある |

他 PC から「検索して開く」までやりたいなら、**両方から同じ UNC で届く場所**をインデックスの主戦場にするのが安全です。

### 5. サーバー側の運用注意

- Everything を終了・スリープ・休止にすると、クライアントは突然「接続失敗」になる
- Wi‑Fi を切り替える・VPN を張ると、IP や到達経路が変わる
- 社外公開やポート転送はしない（この文書は **ローカル LAN 専用**）
- HTTP は平文です。信頼できる LAN 内でも、認証を付ける・不要なら止められるようにする

## クライアント側（すぐサーチ を使う PC）

### 1. 接続設定を入れる

すぐサーチ の **接続設定** タブ:

| 項目 | 入れるもの |
|------|------------|
| ホスト / IP | サーバー PC の LAN IP（例: `192.168.1.10`）。**`127.0.0.1` は自分自身**なので他 PC の Everything には届かない |
| ポート | サーバーと同じ番号（例: `8888`） |
| ユーザー名／パスワード | Everything 側で設定しているときだけ |

操作:

1. ホスト／ポートを入力（欄をクリックすると **接続履歴** から選べる）
2. **接続テスト** で疎通を確認
3. 問題なければ **設定を保存**

「自身に接続」は **このクライアント PC 自身**の IP を入れるボタンです。  
サーバーが別 PC のときは使いません（サーバー側 PC で自分の IP を確認する用途）。

### 2. 接続テストが失敗するとき（クライアント視点）

順番に見る:

1. サーバー PC で Everything が起動し、HTTP が有効か
2. サーバー自身で `http://127.0.0.1:8888/` が開けるか
3. クライアントからブラウザで `http://（サーバーIP）:8888/` が開けるか  
   - ここでダメ → **IP・ポート・ファイアウォール・同一 Wi‑Fi・AP 分離**を疑う  
   - ここで OK なのに すぐサーチ だけダメ → ホスト／ポートの打ち間違い、認証の食い違い
4. ゲスト Wi‑Fi や「端末隔離」になっていないか（スマホ用ゲストは PC 同士不可が多い）
5. VPN 接続中でないか（会社 VPN だとローカル LAN が見えなくなることがある）

### 3. 検索はできるが「開く」「ファイルコピー」がダメなとき

HTTP 接続は成功していても、結果のパスがクライアントから見えないと失敗します。

| 操作 | 何が必要か |
|------|------------|
| **パスのコピー** | テキストだけ。パスが無くても「文字列としては」コピーできる |
| **開く / フォルダを開く** | そのパスがクライアントのエクスプローラーで開けること |
| **ファイルコピー**（エクスプローラーへ貼り付け） | クライアントがそのファイル実体に届くこと |

よくある食い違い:

- 結果が `C:\Users\...`（サーバーのローカル）→ クライアントの `C:\` とは別人のディスク
- 結果が `S:\図面\...` → クライアントに `S:` が無い、または別共有を指している  
  → 対象フォルダや運用を **UNC（`\\サーバー\共有\...`）** に寄せる

### 4. 対象フォルダの指定

検索タブの対象フォルダは、**Everything が知っているパス表記**に合わせます。

- サーバーが UNC でインデックスしているなら、クライアントも `"\\サーバー\共有\フォルダ"` 形式が無難
- サーバーだけが分かる `C:\...` を指定しても、ヒットの意味はサーバーローカルのまま

### 5. クライアント側のその他

- 接続先・パスワードは **その PC のユーザーごとに**保存される（別 PC では入れ直しが必要）
- パスワードは Windows の仕組みで暗号化保存されるため、**別ユーザー／別 PC では復号できない**
- アプリの更新は各クライアントで行う（接続設定とは別）
- ファイアウォールの「送信」は通常そのままでよい（問題になるのは主にサーバーの受信）

## 短いチェックリスト

### サーバー PC

- [ ] Everything 起動中（スリープしない）
- [ ] HTTP サーバー有効・ポート控え済み
- [ ] 必要ならユーザー名／パスワード設定
- [ ] `everything-http-tool.bat` で診断＋ファイアウォール許可（プライベート）
- [ ] LAN IP を把握（可能なら DHCP 予約）
- [ ] 他 PC から開かせたいデータは UNC / 共有でインデックス

### クライアント PC

- [ ] ホストにサーバーの LAN IP（`127.0.0.1` ではない）
- [ ] ポートがサーバーと一致
- [ ] **接続テスト**成功
- [ ] ブラウザでも `http://サーバーIP:ポート/` が開けると安心
- [ ] 「開く」「ファイルコピー」は、結果パスがこの PC から見えるか確認

---

## やってはいけないこと

- Everything の HTTP を **インターネット側にポート開放**する
- 認証なしのまま、来客用・不特定多数の Wi‑Fi に載せる
- クライアントに `127.0.0.1` を入れて「他 PC の Everything」に繋ごうとする
- 接続テスト成功だけ見て、サーバーローカルの `C:\` パスを全員が開けると思い込む
